# Implementation notes

- The application uses the Rails API stack with Active Record and PostgreSQL. Mail, browser assets, file storage, Action Cable, Active Job, and deployment scaffolding are omitted. Later delivery work will use database rows as its durable work source.
- Development and test use explicitly configured, separate database URLs. Test-environment boot rejects a database name matching development or production before schema preparation. Minitest runs in one process to keep local resource use bounded.
- All six domain records use PostgreSQL-generated UUIDs. Unique indexes protect tenant/event idempotency keys, event/endpoint delivery pairs, credential digests, and delivery/run/attempt identities. Endpoint URLs are intentionally not unique: separate registrations represent separate destinations.
- Deliveries reference both events and endpoints through composite foreign keys containing `tenant_id`. A valid resource UUID cannot be linked to a delivery belonging to another tenant. Associations alone do not provide API authorization.
- Events retain parsed JSON data and the exact outbound bytes supplied at creation. Persisted events are read-only in Rails; a PostgreSQL trigger rejects updates and deletes, including bulk writes. The original fan-out count is immutable. The SQL schema format preserves the trigger when rebuilding a database, as described in the [Rails migration guide](https://guides.rubyonrails.org/v8.1/active_record_migrations.html#using-the-sql-schema-dumper).
- Check constraints bound attempt numbers to 1–8, require positive run numbers, constrain states and outcomes, and keep schedules and completion timestamps consistent with row state. A partial unique index permits at most one in-progress attempt per delivery across runs. Cross-row counter updates, legal state transitions, leases, and replay serialization still require transactional services.
- Credentials have a digest field and revocation timestamp; issuance and authentication are not implemented. Endpoints reserve a required ciphertext field for signing secrets; encryption, secret generation, URL validation, and disabling behavior are not implemented. No plaintext signing-secret attribute is provided.
- Setup prepares both local databases without resetting them. Checks run with the test environment and include Rails' Zeitwerk autoload validation.
- The application does not yet implement authenticated tenant isolation, outbound safety, retries, or worker concurrency behavior.
- Version selection was checked against the official [Ruby maintenance branches](https://www.ruby-lang.org/en/downloads/branches/), [Rails releases](https://rubyonrails.org/releases), [Rails maintenance policy](https://rubyonrails.org/maintenance), and [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/). Rails 8.1 remains under security maintenance through October 10, 2027; its listed general bug-fix window has ended. Review supported patch releases before subsequent upgrades.
